1. Architecture & Flow

PopPay utilizes a high-efficiency matching engine combining unique dynamic order amounts and automated Gmail credit alerts (FamApp / UPI notifications) with cryptographic DKIM validation.

STEP 01
Order Creation
Your backend calls POST /api/v1/orders with amount and secret key. PopPay reserves a unique paise amount (e.g., ₹499.18).
STEP 02
1-Click UPI Payment
Customer opens PopPay modal or hosted page. On mobile, taps PhonePe/GPay/Paytm. On desktop, scans dynamic QR code.
STEP 03
Instant Bank Alert
Funds land directly in merchant’s account. Bank dispatches credit alert. PopPay worker matches amount + timestamp.
STEP 04
Webhook & Fulfillment
PopPay sends HMAC-signed webhook payment.success to your server. Checkout UI updates to PAID in real time.

    |                         |                            |                         |                    |

    |                         |--- 2. POST /orders ------->|                         |                    |

Key Concept: Unique Amount Allocation (payableAmount)

To distinguish concurrent payments without requiring customers to manually enter memos, PopPay dynamically assigns a small paise suffix (e.g., base ₹500.00 becomes ₹500.27).

  • Always charge and display order.payableAmount, never the requested baseAmount.
  • Orders expire after 10 minutes if unpaid.

2. Credentials & Security

During account onboarding or via Dashboard → Settings → Credentials, you receive four cryptographic keys:

Credential Prefix Purpose Environment
Public Key pp_live_... Merchant identifier for frontend checkout.js SDK modal Client-side Safe
Secret Key pp_secret_... Authenticates /api/v1/orders backend requests Server-only (Private)
Signing Secret pp_sign_... Validates payment status signatures: HMAC(order_id|payment_id) Server-only (Private)
Webhook Secret whsec_... Verifies X-PopPay-Signature on incoming webhooks Server-only (Private)
⚠️ Security Rule: Never expose POPPAY_SECRET_KEY, POPPAY_SIGNING_SECRET, or POPPAY_WEBHOOK_SECRET in client-side code, git repositories, or mobile bundles. Store them in your server’s environment variables.

3. Quickstart in 3 Minutes

PopPay offers three flexible ways to present the checkout to your customers:

Option A: Drop-in SDK Modal (Recommended)

Modern Popup

Customers never leave your site. Include the lightweight script https://poppay.tech/checkout.js, pass your Public Key (pp_live_...) and order_id.

Frontend HTML + JavaScript Integration

<script>
document.getElementById('pay-btn').addEventListener('click', async () => {
  // Step 1: Create order on your backend
  const res = await fetch('/api/create-order', { method: 'POST' });
  const order = await res.json(); // { order_id: "order_..." }

  // Step 2: Open PopPay modal
  const checkout = new PopPay({
    key: 'pp_live_YOUR_PUBLIC_KEY', // Public Key from PopPay Dashboard
    order_id: order.order_id,         // Order ID from backend
    name: 'My Store',
    handler: async (payment) => {
      // Step 3: Payment verified! Verify signature on your server:
      console.log('Payment successful!', payment);
      // payment contains: { order_id, payment_id, utr, signature }
      
      const verifyRes = await fetch('/api/verify-payment', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify(payment)
      });
      const result = await verifyRes.json();
      if (result.verified) {
        window.location.href = '/order-confirmed?order_id=' + payment.order_id;
      }
    },
    onDismiss: () => {
      console.log('Customer closed the payment window');
    }
  });

  checkout.open();
});
</script>

Zero Client JS

6. Server-Side Payment Verification

When a payment succeeds, the frontend modal receives: 

{
  "order_id": "order_7A0SnT-Mr-S3",
  "payment_id": "6ad42d8d2b5c06d1e98b5bd0",
  "utr": "005983102475",
  "signature": "b1518d0c011ffb88cfe5e02a1167fb21d04a8dcd6ce2985a7fe09b10fe50b2fe"
}

Verification Algorithm

Compute HMAC-SHA256 of {order_id}|{payment_id} using your POPPAY_SIGNING_SECRET: 

signature = HMAC_SHA256(key = POPPAY_SIGNING_SECRET, message = "{order_id}|{payment_id}")
const crypto = require('crypto');

function verifyPayment(orderId, paymentId, signature) {
  const expected = crypto
    .createHmac('sha256', process.env.POPPAY_SIGNING_SECRET)
    .update(`${orderId}|${paymentId}`, 'utf8')
    .digest();

  let supplied;
  try {
    supplied = Buffer.from(signature, 'hex');
  } catch {
    return false;
  }

  return supplied.length === expected.length && crypto.timingSafeEqual(supplied, expected);
}
import hmac
import hashlib

def verify_payment(order_id: str, payment_id: str, signature: str, secret: str) -> bool:
    message = f"{order_id}|{payment_id}".encode("utf-8")
    expected = hmac.new(secret.encode("utf-8"), message, hashlib.sha256).hexdigest()
    return hmac.compare_digest(signature.lower(), expected.lower())

7. Webhooks & Idempotency

PopPay delivers real-time HTTPS webhooks for confirmed payments directly to your server.

Verifying Webhook Signatures

Incoming requests contain the header: 

X-PopPay-Signature: <64-character-hex-digest>

The signature is computed over the raw request body buffer using POPPAY_WEBHOOK_SECRET.

Express Webhook Handler with HMAC-SHA256 Verification 
const express = require('express');
const crypto = require('crypto');

const app = express();

// IMPORTANT: Use express.raw({ type: 'application/json' }) before express.json()
app.post('/webhook', express.raw({ type: 'application/json' }), (req, res) => {
  const signature = req.get('X-PopPay-Signature') || '';
  const expected = crypto
    .createHmac('sha256', process.env.POPPAY_WEBHOOK_SECRET)
    .update(req.body)
    .digest();

  const supplied = Buffer.from(signature, 'hex');
  if (supplied.length !== expected.length || !crypto.timingSafeEqual(supplied, expected)) {
    return res.status(401).json({ error: 'Invalid signature' });
  }

  const payload = JSON.parse(req.body.toString('utf8'));
  if (payload.event === 'payment.success') {
    const { order_id, payment_id, utr, amount } = payload;
    console.log(`Fulfilling order: ${order_id}, UTR: ${utr}, Amount: ₹${amount}`);
    
    // TODO: Idempotently fulfill order, activate plan, or credit user account
  }

  return res.json({ received: true });
});

8. Status Polling API

GET https://poppay.tech/api/v1/checkout/:orderId/status

Public endpoint; safe to call without secret keys to check order progression (PENDING ➔ PAID or EXPIRED). 

const response = await fetch(`https://poppay.tech/api/v1/checkout/${orderId}/status`);
const data = await response.json();

if (data.status === "PAID") {
  console.log("Confirmed UTR:", data.utr);
  console.log("Signature:", data.signature);
}

🛠️ Troubleshooting & Best Practices

  1. Exact Amount Matching:
    Customers must pay the exact amount including paise (e.g., ₹499.18). Any amount deviation is flagged as UNMATCHED in your dashboard to protect against under/over payments.
  2. 10-Minute Verification Grace:
    The checkout window is 10 minutes. Bank alert emails are accepted through an additional 10-minute grace window. The email’s timestamp is parsed strictly in IST (Asia/Kolkata) and matched reliably against UTC server windows.
  3. Auto-Reconciliation Worker:
    PopPay's background worker scans every 10 seconds. Any unmatched payments are automatically reconciled against active pending orders.
  4. Cryptographic DKIM Strictness:
    FamApp payment alert emails are validated cryptographically against famapp.in DKIM pass records. Forged or forwarded emails from unauthorized senders fail verification by design.
